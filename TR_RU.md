## Часть 1. Основной документ.

### 1. Заголовок и базовая информация.

• **Название:** Tetro Rally

• **Назначение:** Проект № 14. Продукт.

• **Фаза проекта:** Phase II.

• **Технологический стек:** Python (библиотека Pygame).

• **Статус проекта:** Полностью завершен.

### 2. Краткое описание проекта.

**Tetro Rally** – это аркадная игра в жанре «Тетрис» с элементами соревнования, созданная на языке Python с использованием библиотеки Pygame.

Игрок сражается против встроенного бота, который автоматически принимает решения о размещении фигур на основе эвристической оценки игрового поля.

Оба поля (игрока и бота) отображаются одновременно, а победа определяется по принципу «кто первый проиграет» — тот, чьё поле заполнится до верхней границы, терпит поражение.

В данной версии проекта реализованы такие элементы как: главное меню, экран помощи, экран завершения игры (Game Over), система предпросмотра следующей фигуры, а также сохранение лучшего результата в файл.

Проект представляет собой полностью функциональную версию игры с широким пользовательским интерфейсом, продвинутой игровой логикой и искусственным интеллектом противника.

### 3. Четкие цели проекта.

• Создать работающую версию соревновательного «Тетриса» с понятным управлением.

• Реализовать основные игровые механики: появление фигур, их падение, вращение, перемещение и удаление (при заполнении линии).

• Реализовать систему состояний приложения (menu, help, game, game_over).

• Добавить систему предпросмотра следующей фигуры для игрока и бота.

• Реализовать систему подсчета очков и сохранения лучшего результата в JSON-файл.

• Обеспечить корректную обработку столкновений с границами поля и другими фигурами.

• Реализовать бота-противника с алгоритмом оценки игрового поля.

• Реализовать систему сдвигов (wall kick) при вращении фигур у границ.

• Обеспечить стабильную работу игры с заданной частотой кадров (60 FPS).

• Продемонстрировать подход к разработке игровых приложений с пользовательским интерфейсом и ИИ.

### 4. Компоненты проекта.

Проект состоит из одного исполняемого файла, который включает в себя все компоненты:

• **tetro_rally.py** – основной скрипт, содержащий весь код игры, включая игровую логику, интерфейс, ИИ бота и систему управления состояниями.

• **tetro_rally_data.json** – файл сохранения лучшего результата (создается автоматически при первом завершении игры).

### 5. Инструкция по использованию.

- **5.1. Запуск:**

• Убедитесь, что установлена библиотека Pygame (pip install pygame).

• Запустите скрипт с помощью Python (например, с помощью PyCharm).

- **5.2. Цель игры:**

• Заполняйте горизонтальные линии падающими фигурами, чтобы зарабатывать очки.

• Игра завершается, когда одна из сторон (игрок или бот) не может разместить новую фигуру.

• Если игрок проигрывает первым — побеждает бот, если бот — побеждает игрок.

• Лучший результат игрока сохраняется в файл.

- **5.3. Управление:**

• Стрелка ВЛЕВО (←): переместить активную фигуру влево.

• Стрелка ВПРАВО (→): переместить активную фигуру вправо.

• Стрелка ВНИЗ (↓): ускорить падение активной фигуры.

• Стрелка ВВЕРХ (↑): повернуть активную фигуру на 90° по часовой стрелке.

• ПРОБЕЛ (Space): мгновенное падение фигуры до упора.

• ESC: выход в главное меню.

• Мышь: управление кнопками в меню, экране помощи и Game Over.

- **5.4. Интерфейс:**

• Главное меню с кнопками Play и Help и лучшим счетом Best Score.

• Экран помощи с описанием управления и правил.

• Два игровых поля размером 10x20 клеток (игрок слева, бот справа).

• Верхняя панель, отображающая:

• текущий счет игрока (PLAYER)

• текущий счет бота (BOT)

• надпись VS между счетами

• следующую фигуру игрока и бота (NEXT)

• Черные клетки с серой сеткой – пустое пространство.

• Цветные клетки – установленные или падающие фигуры.

• Экран Game Over с результатом матча и кнопками Play Again и Main Menu.

- **5.5. Система очков:**

• 1 линия — 10 очков

• 2 линии — 30 очков

• 3 линии — 60 очков

• 4 линии (Tetro) — 100 очков

## Часть 2. Технический документ.

### 1. Цели разработки.

• Основной целью разработки было создание расширенной соревновательной модели классической игры Tetris для закрепления навыков программирования на Python и работы с библиотекой Pygame.

• Дополнительно проект направлен на изучение построения пользовательского интерфейса, управления состояниями приложения, работы с файловой системой (JSON) и реализации простого искусственного интеллекта для бота-противника.

• Задачи включали работу с матрицами (игровыми полями), обработку пользовательского ввода, реализацию системы столкновений, временных интервалов и базовой архитектуры игрового цикла.

### 2. Использованные технологии.

• **Язык программирования:** Python

• **Графическая библиотека:** Pygame

• **Стандартные библиотеки:** random (для генерации фигур), json (для работы с файлами сохранения), os (для проверки существования файла сохранения).

### 3. Архитектура проекта.

• Проект реализован как монолитное приложение с элементами конечного автомата состояний.

• Основной цикл: while running:.

• Логика разделена по состояниям:

• menu – главное меню.

• help – экран помощи.

• game – игровой процесс.

• game_over – экран завершения игры.

• В каждом кадре выполняются: обработка событий, обновление состояния, проверка игровой логики, отрисовка.

• В игровом процессе одновременно работают две независимые подсистемы: логика игрока и логика бота.

### 4. Структура проекта.

• **Инициализация:** настройка Pygame, создание окна, шрифтов, кнопок, цветов и параметров игры.

• **Глобальные переменные:** player_board, bot_board, player_piece, bot_piece, player_next, bot_next, player_score, bot_score, best_score, state, winner и другие.

• **Игровой цикл:** основной цикл, в котором происходит управление состояниями и логика игры.

• **Класс Piece:**

• __init__(shape_id=None) – создание фигуры (случайной или по индексу).

• rotate() – поворот фигуры на 90°.

• cells() – возвращает список координат всех заполненных клеток фигуры.

• **Функции работы с доской:**

• create_board() – создание пустого игрового поля.

• valid_position(piece, board, dx, dy) – проверка возможности размещения фигуры.

• lock_piece(piece, board) – фиксация фигуры на доске.

• clear_lines(board) – удаление заполненных линий.

• calculate_score(lines) – расчет очков за удаленные линии.

• spawn_piece(next_piece) – появление новой фигуры.

• **Функции ИИ бота:**

• get_column_heights(board) – получение высоты каждой колонки.

• count_holes(board) – подсчет «дырок» (закрытых пустых клеток).

• board_score(board, cleared_lines) – эвристическая оценка игрового поля.

• simulate_move(piece, board, rotation, x_position) – симуляция хода.

• bot_find_best_move(piece, board) – поиск лучшего хода.

• execute_bot_move() – выполнение хода бота.

• **Функции отрисовки:**

• draw_text(), draw_button(), draw_board(), draw_preview(), draw_top_panel(), draw_menu(), draw_help(), draw_game_over().

• **Функции управления игрой:**

• reset_game() – сброс игры.

• spawn_player(), spawn_bot() – появление фигур.

• lock_player() – фиксация фигуры игрока.

• finish_game(who_wins) – завершение игры.

• load_best_score(), save_best_score() – работа с рекордом.

### 5. Ключевые компоненты системы.

• **Игровое поле (board):** Двумерный список, где каждый элемент хранит либо None (свободная клетка), либо цвет фигуры (занятая клетка).

• **Фигуры:** представлены в виде матриц (shape), поворачиваются через транспонирование и реверс (zip(*shape[::-1])), выбираются случайным образом из списка SHAPES.

• **Система следующей фигуры:** реализована через player_next и bot_next, отображается на верхней панели.

• **Система коллизий:** проверка границ поля, проверка занятых клеток через valid_position().

• **Система вращения:** вращение вокруг центральной точки с использованием wall kick (сдвигов по X).

• **Система ИИ бота:** эвристическая оценка с учетом:

• количества удаленных линий

• суммарной высоты башен

• количества «дырок»

• максимальной высоты

• «бугристости» (bumpiness)

• Система сохранения рекорда: JSON-файл tetro_rally_data.json.

### 6. Реализация пользовательского интерфейса.

• Интерфейс полностью реализован средствами Pygame.

• Основные элементы: окно приложения, кнопки меню, два игровых поля, верхняя панель, текстовые элементы, экран Game Over.

• Отрисовка выполняется каждый кадр с помощью функций pygame.draw и pygame.font.

### 8. Основные сложности и способы их решения.

• **(1) Сложность:** корректное вращение фигур рядом со стенами и блоками.
**Решение:** реализована система сдвигов при вращении (аналог wall kick).

• **(2) Сложность:** корректное удаление линий и сохранение цвета.
**Решение:** копирование как статуса, так и цвета ячеек.

• **(3) Сложность:** управление состояниями приложения.
**Решение:** введена переменная state и логика переключения между MENU, HELP, GAME, GAME_OVER.

• **(4) Сложность:** реализация ИИ бота без мгновенного размещения.
**Решение:** бот использует задержку bot_thinking и флаг для создания эффекта «раздумий», а также алгоритм поиска лучшего хода через симуляцию.

• **(5) Сложность:** одновременная работа двух игровых полей.
**Решение:** создание независимых player_board и bot_board, а также отдельных объектов фигур для каждого поля.

• **(6) Сложность:** корректное определение победителя.
**Решение:** функция finish_game(who_wins) вызывается при невозможности разместить новую фигуру одной из сторон.

### 9. Текущие ограничения проекта.

• Отсутствие уровней сложности для бота.

• Бот использует только одну эвристическую стратегию (без обучения).

• Код остается монолитным (без разделения на модули).

• Нет звуковых эффектов.

• Нет возможности играть в кооперативе или с другим игроком.
